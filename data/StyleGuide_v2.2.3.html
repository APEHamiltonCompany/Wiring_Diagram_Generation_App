1. Document Guide

1.1 Rules for Using This Guide - For Humans

This StyleGuide is a comprehensive reference for Large Language Models (LLMs) to generate wiring diagrams. They are not perfect and will need modification afterwards. The first prompt is to let the LLM learn the specifications for generating wiring diagrams, the second and subsequent prompts are to give the system details.

1.1.1 Prompt Instructions

Prompt 1 - Initial Setup:

Read through and analyze the uploaded document completely. Follow the Rules for Using This Guide - For LLMs. After you finish, I will ask you to generate diagrams. Thoroughly read all sections.

1.1.2 Input Field Guidelines

Filename:

  • Make sure to include the extension.drawio so the LLM knows exactly what you want the end result to be
  • Sometimes it tries to make a PNG or other visual representation - we need to modify these after, so we'll need it to be a.drawio file

Pipettor:

  • The LLM will decide which pipettor structure to use based on this name
  • If there's no AC box in the VANTAGE, just remove it (these sorts of exception conditions can break other things, so avoid adding complexity)
  • All STARline names (STAR, STARplus, STAR-2) use the same pipettor structure

Devices:

  • Accepts a comma-separated list of devices
  • The LLM will look through the Device Reference Database (DRD) for device information
  • If a device is not in the DRD, the LLM should prompt you to input the details
  • NOTE: There are still many devices missing and some information may be incorrect - keep this in mind
  • Eventually, all we'll need to do is input a Sales Order number

PC:

  • Accepts: Standard, Industrial, L3, or Customer-supplied PC
  • All these have different rules for when to use hubs - the LLM will decide when they are needed
  • PC types can also be specified if they're on the Sales Order

Facility:

  • Currently supports 20A or 15A circuits
  • There are rules for using power strips and optimizing power distribution
  • The LLM handles this well, but there may be trouble with other circuit requirements (e.g. European 220V)

1.1.3 Workflow and Tips

Approval Process:

  • After taking in all information, the LLM will provide a summary and wait for approval before generating the diagram
  • This is when the LLM will ask for missing device information
  • Be sure to check the summary - this is when you catch mistakes
  • If there are mistakes or new information is given after generation, the LLM will update the document and provide a new version

Post-Generation:

  • Open up the.drawio file and adjust how some lines are laid out
  • The diagram is then complete

Performance Note:

  • The first time will take a while to analyze the document
  • Keep using the same chat and you'll be cutting wiring diagram creation time to just a few minutes

5.4 HHS/HHC Communication Rules

Hamilton Heater Shaker (HHS) and Hamilton Heater Cooler (HHC) devices have special communication requirements depending on their configuration:

Basic Rules:

  • First HHS device: Connects to PC via USB A to B cable
  • Subsequent HHS devices: Do NOT connect to PC (only connect to HHS Control Box)
  • First HHC device: Connects to PC via USB A to micro cable
  • Subsequent HHC devices: Do NOT connect to PC (only connect to HHS Control Box)

Mixed HHS/HHC Configuration: When both HHC and HHS devices are connected to a single HHS Control Box:

  • Only the first HHC connects to PC (USB A to micro)
  • No HHS devices connect to PC
  • All HHS and HHC devices still connect to HHS Control Box via DB9 serial

Multiple HHS Control Boxes: When using multiple HHS Control Boxes in a single system:

  • One device per control box must be connected to PC for communication
  • Follow the priority: First HHC if present, otherwise first HHS
  • All other devices on that control box do not connect to PC

Pipettor Direct Connection (No Control Box):

  • Microlab STAR TCC Ports: When HHS/HHC connect directly to Microlab STAR TCC ports without an HHS Control Box, no additional communication cables are needed (communication happens through the TCC port connection)
  • Microlab VANTAGE Periphery Box: When HHS/HHC connect directly to Microlab VANTAGE periphery box without an HHS Control Box, all devices need USB connections to the PC (follow USB cable specifications in device reference)

CRITICAL: All HHS and HHC devices must always connect to the HHS Control Box via DB9 serial connections, regardless of PC communication setup.

8. Diagram Creation Workflow

Reorganization note: Hub/PC and power calculations are centralized in Sections 4 and 3. This section defines sequence and execution rules.

★ CRITICAL SPACING RULE - READ FIRST: Apply the authoritative spacing specification in Section 9.1.1 before routing any line or placing any element.

This applies to: Device blocks, PC blocks, Hub blocks, Pipettor blocks, Power strips, Circuits, All connection lines, Dashed separator lines, Legend box, Any other diagram elements.

8.1 Step Order and Execution Details

  1. Step 1: Determine Hub Requirements and PC power inputs based on PC Type Specifications (Section 4.1) and PC power specifications (DRD §3).
  2. Step 2: Calculate Power Distribution (Section 3.5).
  3. Step 3: Add Elements Per-Circuit Order.
  4. Step 4: Handle Pipettor Connection Timing.

8.1.1 Step 1 - Hub Requirement Check

Use Section 4.1 PC type specifications (ports) and DRD §3 (power) to determine whether any USB hub, serial hub, or router/switch is required before placing downstream devices.

8.1.2 Step 2 - Power Distribution Calculation

  • Apply the 80% circuit loading rule (15A circuit: 12A usable, 20A circuit: 16A usable).
  • Optimize to use the fewest circuits while keeping routing clean and compliant.
  • Ensure Circuit 1 includes the PC.
  • Use power strips only when a circuit has more than 2 connections.
  • Standard PC requires 2 power connections (2x C13 to NEMA 5-15), which can force a power strip on Circuit 1 when total connections exceed 2.

8.1.3 Step 3 - Add Elements Per-Circuit Order

Process circuits strictly in order (Circuit 1, Circuit 2, etc.) and finish each circuit layout before moving to the next one.

8.1.4 Step 4 - Pipettor Connection Timing

Add the pipettor block when a pipettor-connected device is required.

IMPORTANT: Do NOT connect pipettor communication and power until the pipettor's circuit is next in the ordered sequence.

9. Line Spacing & Routing Rules

Reorganization note: This section merges spacing rules, connector behavior, and connection placement rules.

9.1 The 10px Rule

CRITICAL RULE: Section 9.1.1 is the PRIMARY and AUTHORITATIVE 10px spacing rule for all diagrams. If any other sentence appears to conflict, follow Section 9.1.1.

9.1.1 Comprehensive 10px Spacing Rule (PRIMARY/AUTHORITATIVE)

Non-available space concept: Every placed element creates a 10px exclusion perimeter where no unrelated line segment or element edge may enter. The non-available space is part of the routing obstacle and must be respected before route generation and while refining paths.

Occupied area and non-available perimeter formula: For an element with origin (x, y), width w, and height h:

  • Occupied space: [x, x+w] × [y, y+h]
  • Non-available perimeter bounds: [x-10, x+w+10] × [y-10, y+h+10]
  • Valid orthogonal line routing for unrelated segments: X ≤ (x-10) OR X ≥ (x+w+10) OR Y ≤ (y-10) OR Y ≥ (y+h+10)

PC example (mandatory reference example): PC origin (600, 160), dimensions 120×80.

  • Occupied space: [600, 720] × [160, 240]
  • Non-available perimeter bounds: [590, 730] × [150, 250]
  • Lines must route at: X ≤ 590 OR X ≥ 730 OR Y ≤ 150 OR Y ≥ 250

Device-to-device spacing formula: For Device A (x1, y1, w1, h1) and Device B (x2, y2, w2, h2), separation is valid only if one condition is true: x2 ≥ x1+w1+10 OR x1 ≥ x2+w2+10 OR y2 ≥ y1+h1+10 OR y1 ≥ y2+h2+10.

Applies to all elements: device blocks, PC blocks, hubs, pipettors, power strips, circuits, all connector types, dashed separators, legend blocks, labels, and diagram boundaries.

Line-to-line and multi-connection rule: parallel orthogonal segments and same-device connection lanes must maintain the same 10px minimum clearance; use arc jumps for crossings.

9.1.2 Routing Guidelines

  • Lines connect to device faces (top, bottom, left, right) - never corners.
  • Use orthogonal (90°) routing only
  • When lines cross, use arc jumps (jumpStyle=arc)
  • Waypoint routing note: Always include explicit waypoint points (<Array as="points">) to route around obstacles (device boxes, labels, legends, and other diagram elements) while maintaining Section 9.1.1 spacing clearances.
  • Line attachment: Attach lines to devices using only source and target. Do not lock lines to fixed connection points on the device; lines must remain free to move along the device face. Use waypoints to control routing.

9.1.3 Enhanced Line Spacing Rules

No Overlap Rules:

  • Lines should NOT overlap with each other
  • Lines should NOT overlap with any other elements (devices, hubs, power strips, etc.)
  • For numeric clearance and parallel lane spacing requirements, use Section 9.1.1 as the sole authoritative reference.

Multiple Connections to Same Element: Connection point separation and lane spacing must follow Section 9.1.1.

9.3.6 PC Connection Placement Rules

Devices to Main PC:

  • Prioritize connections to the bottom face of the main PC
  • Route USB, Serial, and Ethernet connections from devices to the bottom of the PC block
  • This creates cleaner routing and better visual organization

  • This maintains consistent power routing from left (facility/power) to right (devices)
  • Applies to all PC types (main PC, additional PCs, Industrial PC, etc.)
